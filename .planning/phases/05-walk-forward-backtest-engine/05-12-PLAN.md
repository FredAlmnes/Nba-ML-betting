<objective>
Run the backtest for real, once, over the whole train/calibrate slice — then hold the single
blocking checkpoint that turns eleven plans of plumbing into a decision.

Everything before this plan built an engine and proved its parts correct on synthetic fixtures
and two-week smoke windows. Nothing before this plan has answered the question the milestone
exists to answer: over 2022-23 and 2023-24, does this strategy make money, and how much
confidence does that number deserve. This plan produces that answer, presents it honestly —
bet count, confidence interval, every skip counter, the four Kelly arms side by side — and
then asks the developer to freeze the configuration.

The freeze matters because plan 05-13 spends the holdout. BT-03 allows exactly one look at
2024-25 for this milestone; there is no second one. Any threshold or staking value changed
after that look is tuned on the holdout, which is precisely the failure mode
`.planning/REQUIREMENTS.md` names as "exactly how the current losing thresholds were arrived
at". So the freeze must happen before, must be explicit, and must be written down in a form
plan 05-13 can read back and check itself against.

Purpose: BT-04's "confidence interval attached to every headline number" and BT-05's
"before/after comparison against the current losing live configuration" only become real when
a human has actually looked at the numbers and accepted them; BT-07's sweep only becomes a
decision when someone picks an arm.
Output: `05-FROSNE-BESLUTNINGER.md` (run evidence + the frozen parameter table + plan 05-13's
exact invocation), a closed-out `05-VALIDATION.md`, and one real `backtests/<run_id>/`
directory holding `manifest.json`, `ledger.csv` and `kelly_sweep.json`.

This plan writes no production code. It modifies two planning documents and runs one
already-shipped CLI.
</objective>

planning. This plan's run must reproduce them; a mismatch is a regression, not a surprise.

- **Full train/calibrate predict pass** at `min_treningskamper=100`
  (`05-07-PLAN.md` §verified_data_facts): `datoer_totalt` **318**,
  `datoer_hoppet_over_for_lite_treningsgrunnlag` **15**, `datoer_behandlet` **303**,
  `kamper_totalt` **2 302**, `retreninger` **13** (months 2022-11 .. 2024-04).
- **Warm-up floor.** The first game date is 2022-10-24 and its strictly-earlier training
  window holds zero rows. With threshold 100 the first runnable date is **2022-11-09**;
  15 dates / 111 games are skipped before it. This is why `datoer_behandlet` is 303, not 318,
  and it is expected — not a data gap.
- **Closing-snapshot gaps.** Exactly two games in the whole feature table have no `closing`
  snapshot: `2023-03-11` PHX(1610612756) vs SAC(1610612758) — inside the train/calibrate
  slice — and `2025-01-09` DAL(1610612742) vs POR(1610612757) — inside the holdout. So this
  plan's run can carry at most **one** game with `kamper_uten_closing_snapshot`, and at most
  one bet with `bets_uten_clv`.
- **Expected bet-count order of magnitude.** `05-RESEARCH.md` Pattern 5 estimated
  **~190-360 flagged bets** on the train/calibrate slice, from an assumed 8-15 % value-flag
  rate over 2 413 games. Against the 2 302 games this run actually scores, the same rate band
  is **~185-345 flagged candidates**. Placed bets are strictly fewer than flagged candidates,
  because the injury filter, the Kelly-edge floor and dedup each remove some. Treat the band
  as an order-of-magnitude sanity check on `kandidater_flagget`, never as an assertion.
- **The "inconclusive" line.** Prior-milestone `PITFALLS.md` flags **under ~300-500 placed
  bets** as statistically inconclusive. A wide bootstrap CI at this sample size is the correct
  outcome, not a defect — BT-04 attaches the CI precisely so this is visible.
- **Cost.** A full XGBoost + isotonic fit on ~2 500 rows takes ~0.4 s, so 13 retrains cost
  seconds; the whole predict pass is roughly 10-15 s and each sweep arm is pure arithmetic
  over a few hundred cached rows. No Odds API credits are spent — the engine reads only the
  already-archived `odds_arkiv.db`.
- **Accepted data-quality boundaries** (surface them, do not investigate them as bugs):
  thinner eu-region bookmaker coverage in early 2022-23 (10-11 bookmakers/game vs 17-19 later,
  measured in Phase 4 and accepted by the developer), and the closing-line gap game above.
