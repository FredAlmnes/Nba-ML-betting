plan writes it, and writes the structural assertions that stop it from becoming a green light
that means nothing.

That second half matters more than it sounds. A parity test between two paths is the easiest
test in this repo to make pass vacuously: if both paths flag zero bets, `[] == []` is true and
the suite goes green while the live bot and the backtest have silently diverged on the exact
thing this milestone's go/no-go decision rests on. Every extra assertion in this plan exists to
make that outcome impossible — the fixture is pinned to a case where both paths MUST flag
exactly one bet, and one test deliberately forces a disagreement and requires the comparison to
fail.

Finally, this plan runs the phase's first full-suite gate: the 129 pre-Phase-5 tests and every
test added by plans 05-01 through 05-10 green together in one `python3 -m pytest tests/ -q`.

Purpose: BT-02 requires that nothing post-decision reaches the loop; the strongest available
evidence for that is that the loop's decision is byte-for-byte the same decision the live bot
makes from the same inputs. Output: an extended `tests/test_parity.py` and this plan's rows
filled into `05-VALIDATION.md`.
