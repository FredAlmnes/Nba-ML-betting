<known_defect>
**`beregn_lag_form` does not read its own parameter.** `02_feature_engineering.py:35` declares `def beregn_lag_form(df_raw, vindu=10)`, but the body references the module-level global `df` three times — lines 61 (`hjemme_df = df[...]`), 78 (`borte_df = df[...]`) and 79 (`borte_df["VANT"] = 1 - df["HJEMME_VANT"].values`). `df_raw` is never used. The single call site is `beregn_lag_form(df, vindu=10)` at line 100, passing that exact global, so the current output is correct by coincidence.

This must be fixed during extraction — a function that ignores its argument cannot be imported by `04_value_detector.py`, cannot be called with a fixture, and cannot be given an `as_of` cutoff. Replace all three `df` references with `df_raw`. Because the only caller passes the global as the argument, this is provably output-preserving, and the golden-file check in Task 3 proves it empirically.

This is the one code change in this plan that is not pure relocation. Per RESEARCH.md Pitfall 1, it must be named explicitly in the commit body and the SUMMARY rather than bundled silently into "extraction".
