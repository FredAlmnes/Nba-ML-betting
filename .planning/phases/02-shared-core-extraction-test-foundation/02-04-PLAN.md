<module_shadowing_warning>
Creating `teams.py` at repo root introduces a **name collision** with `nba_api.stats.static.teams`, which all four call sites currently import as the bare name `teams`. Two consequences the executor must handle deliberately:

1. Inside `teams.py` itself, import the upstream module under an alias — `from nba_api.stats.static import teams as nba_teams` — so the module does not appear to import itself. `nba_api` uses absolute intra-package imports, so its own resolution is unaffected by a repo-root `teams.py`, but the alias keeps the file readable and removes any doubt.
2. At every call site, the line `from nba_api.stats.static import teams` must be **deleted**, not left alongside `from teams import finn_lag`. In each of the four files that import is used for exactly one `get_teams()` call, which this plan removes — so nothing else breaks. Leaving both would shadow one name with the other depending on line order.

Verification for this hazard is an explicit acceptance criterion in Task 3.
</module_shadowing_warning>
