<phase_ordering_note>
Plans 01-06 in this phase are strictly sequential (wave 1 → 6) even where their `files_modified` sets overlap only partially. Reason, unchanged from Phase 1: every plan performs `git add` + `git commit` against a single shared git index. Two agents committing concurrently would (a) race on `.git/index.lock` and (b) risk one plan's `git commit` sweeping in another plan's staged files — the exact failure mode Phase 1's pre-flight gate exists to prevent. Additionally, plans 03, 04 and 05 all edit `04_value_detector.py` and `06_bot.py`, which forces sequencing on file ownership alone. Do not parallelize.

Phase-wide staging rule (binding on every plan 02-06): stage with explicit pathspecs only. `git add -A` and `git add .` are forbidden for the entire phase.
</phase_ordering_note>
