<objective>
Give the backtest engine its numbered entry point: `08_kjor_backtest.py`, a thin `argparse`
wrapper in the exact mould of `07_hent_historisk_odds.py` that calls
`backtest.klargjor_backtestdata` and `backtest.kjor_og_lagre` and owns no backtest logic of
its own.

Everything expensive and everything correctness-critical already exists in `backtest.py`
(plans 05-07 through 05-09). What does not exist yet is the surface a human actually touches,
and that surface is where two specific things go wrong. First, a date typed by hand is the only
untrusted input this phase has: `hent_unike_kampdatoer` filters by *string* comparison, so
`2024-1-5` does not error — it sorts lexically below `2024-10-01` and silently selects a
different window than the person meant, while `2024-13-45` matches nothing and produces a calm
"0 datoer" run. Second, `backtest.py`'s holdout guard is structural, but the CLI can still hand
it a `holdout` argument; a flag layout where some plausible combination of switches lands on the
holdout path would spend BT-03's one-shot evaluation budget with no error and no way back.
Third, that same guard cuts the other way: `kjor_backtest` refuses a date LIST containing any
holdout date in a pre-flight before it does any work, so leaving the upper bound unbounded would
make the plainest possible invocation — `python 08_kjor_backtest.py` with no flags, the one
`KOMME_I_GANG.md` documents — raise `HoldoutLaastFeil` instead of replaying the tuning slice.
The CLI therefore resolves a default `--til` of the day before `config.HOLDOUT_START_DATO`.

Purpose: BT-01's replay needs a way to be run, BT-05's manifest needs its run id surfaced to the
person who must record it, BT-07's sweep needs an on-switch, and BT-03's spend-once guarantee
needs to survive contact with a command line. Nothing here re-derives a number.
Output: `08_kjor_backtest.py`, `tests/test_kjor_backtest.py`, and `KOMME_I_GANG.md`'s step 8.
</objective>

- `odds.hent_unike_kampdatoer(features_fil, fra, til)` filters dates by **string** comparison
  against `fra`/`til`, and `backtest._sikre_ikke_holdout` compares `dato >= config.HOLDOUT_START_DATO`
  the same way. Two consequences, both of which the date validator exists to prevent:
  `"2024-1-5"` sorts BELOW `"2024-10-01"` lexically (the `-` byte is below `0`), so a
  non-zero-padded date silently selects a different window than the operator meant; and
  `"2024-13-45"` matches nothing and produces a calm "0 datoer" run rather than an error.
  `datetime.strptime` with `%Y-%m-%d` accepts the non-padded `"2024-1-5"` in CPython, so
  `strptime` alone is NOT a sufficient guard — the exact-shape check must come first.
- **A bare invocation must not be handed an unbounded upper date bound.**
  `klargjor_backtestdata(fra=None, til=None)` yields all 480 dates in `nba_features.csv`, which
  run through 2025-04-13 — well inside the holdout — and `kjor_backtest`'s pre-flight calls
  `_sikre_ikke_holdout` on every date in that list before any other work (plan 05-07 Task 2), so
  a bare run would raise `HoldoutLaastFeil` before processing a single tuning date. The CLI
  therefore resolves `--til` to the day before `config.HOLDOUT_START_DATO` (2024-09-30 for the
  locked 2024-10-01) whenever the operator gives neither `--til` nor `--holdout`. `--fra` can
  safely stay `None`: the earliest date in the feature table is 2022-10-24, and only the UPPER
  bound can reach the holdout.
- `strategy.beregn_innsats` returns `0.0` for every bet when `kelly_fraksjon` is `0`
  (05-RESEARCH.md Pitfall 6), which reads as a flat strategy that never loses. This is why
  D-05-03 defines the flat arm as a `backtest.py`-local branch and why a `--kelly-fraksjon 0`
  invocation must be refused rather than passed through.
- `KOMME_I_GANG.md` currently documents steps 1-4 only; steps 5, 6 and 7 were never added to it,
  and it writes `python`, not `python3`. Its "Neste steg for å forbedre modellen" list still
  contains the bullet `Backtesting – test modellen historisk for å se lønnsomhet`, which this
  phase delivers.
- `.gitignore` already excludes `backtests/`, `nba_features.csv`, `odds_arkiv.db`,
  `nba_spillerlogg_raw.csv`, `bankroll.json` and `bets.json`. No run artifact this CLI produces
  can reach git, and every real-data test needs a skip guard because a fresh clone has none of
  those inputs.
- The suite collected 129 tests before this phase began; plans 05-02 through 05-09 add their own.
  This plan adds one NEW file, `tests/test_kjor_backtest.py`, and touches no existing test file —
  plan 05-11 owns `tests/test_parity.py` in this same wave and must not be edited here.

  `min_treningskamper=100`) skips its first 15 dates for too little training data and processes
  51. A window starting LATER than that skip boundary therefore processes immediately, which is
