<objective>
Build `backtest.py`'s predict pass: the walk-forward date loop that composes every shared
module Waves 1-4 produced (`model.py`, `odds.py`'s archive readers, `skadefilter.py`'s
as-of health check, `strategy.py`'s value/EV rule) into one chronological replay, and the
structural holdout guard that makes BT-03's "checked exactly once" enforceable by code
rather than by discipline.

This is the first plan in the phase where the pieces actually meet. Everything before it
built a component in isolation with its own tests; this plan is where a wrong composition
(a closing price reaching a decision, a model trained on the game it is scoring, a missing
odds snapshot silently read as "no value") would produce numbers that look plausible and
are wrong. Every guard in this plan exists because that failure mode is silent.

Purpose: BT-01 needs the pipeline replayed chronologically; BT-02 needs every lookup
provably as-of-safe; BT-03 needs the holdout unreachable from tuning code. Staking, ledger,
manifest and the Kelly sweep are deliberately NOT here — plans 05-08 and 05-09 own them and
consume this plan's cached prediction rows.
Output: `backtest.py` (predict pass + holdout guard), `tests/test_backtest.py`, and this
plan's rows filled into `05-VALIDATION.md`.

- `nba_features.csv` holds 3,638 games over 480 unique dates, 2022-10-24 to 2025-04-13.
  Columns: `GAME_ID`, `GAME_DATE_HJEMME`, `TEAM_ABBREVIATION_HJEMME`,
  `TEAM_ABBREVIATION_BORTE`, `HJEMME_VANT`, then 9 `HJEMME_RULL_*`, 9 `BORTE_RULL_*` and
  7 `DIFF_*` columns (30 columns total).
- **The feature table carries no team IDs — only abbreviations.** The archive join key
  needs nba_api team IDs, so the loop must resolve them with `teams.finn_lag()`. All 30
  distinct abbreviations in the file resolve on an **exact** `LAG_OPPSLAG` hit (no substring
  fallback is ever exercised); zero unresolvable names exist in the data.
- With `HOLDOUT_START_DATO = "2024-10-01"`: 2,413 games / 318 unique dates fall in the
  train/calibrate slice (2022-10-24 .. 2024-04-14), and 1,225 games / 162 unique dates in
  the holdout (2024-10-22 .. 2025-04-13). The train/calibrate slice spans 14 distinct
  calendar months.
- **Archive join hit rate is 100%.** Joining every game in `nba_features.csv` to
  `odds_arkiv.db` on `(kamp_dato, hjemme_lag_id, borte_lag_id)`: 2,413/2,413 train games and
  1,225/1,225 holdout games have a `bet_time` snapshot. A healthy full run must therefore
  report `kamper_hoppet_over_manglende_odds == 0`; any nonzero value is a regression in the
  join, not a data gap.
- **Exactly two games in the feature table have no `closing` snapshot**, and they are the
  only source of a missing CLV: `2023-03-11` PHX(1610612756) vs SAC(1610612758) — the same
  gap game plan 05-04 pinned as a golden case — and `2025-01-09` DAL(1610612742) vs
  POR(1610612757). One in each slice.
- **Warm-up is a hard constraint, not a preference.** The first game date is 2022-10-24,
  where the strictly-earlier training window holds **zero** rows, so `model.tren` raises
  `ValueError`. Verified counts of dates/games below the first date whose window reaches a
  given size: threshold 50 → first runnable date 2022-11-01 (8 dates, 55 games skipped);
  **threshold 100 → 2022-11-09 (15 dates, 111 games skipped)**; threshold 150 → 2022-11-14
  (20 dates, 151 games); threshold 200 → 2022-11-21 (27 dates, 200 games). This plan uses
  100 (rationale in Task 2).
- Consequence for a full train/calibrate predict pass: `datoer_totalt` 318,
  `datoer_hoppet_over_for_lite_treningsgrunnlag` 15, `datoer_behandlet` 303,
  `kamper_totalt` 2,302, `retreninger` 13 (months 2022-11 .. 2024-04). These are the numbers
  plan 05-12's run should reproduce; this plan does not run the full pass.
- Smoke window used by Task 3 (`fra="2022-10-24"`, `til="2022-12-31"`,
  `min_treningskamper=100`): `datoer_totalt` 66, skipped 15, processed 51 (first processed

  `kamper_hoppet_over_manglende_odds` 0, `kamper_hoppet_over_ukjent_lag` 0.
- A full XGBoost + isotonic fit on ~2,500 rows takes ~0.4 s (measured in 05-RESEARCH.md), so
  13 retrains cost seconds. Compute is not a constraint anywhere in this plan.
