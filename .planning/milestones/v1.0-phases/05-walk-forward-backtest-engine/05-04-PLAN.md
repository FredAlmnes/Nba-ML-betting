<objective>
Give the backtest a way to read historical prices out of `odds_arkiv.db`, and make that
reading use the exact same "best price per outcome across bookmakers" rule the live bot
already applies — by extracting that rule into one function both paths call.

Two things must be true before plan 05-07's walk-forward loop can price a single bet.
First, the loop needs `(hjemme_odds, borte_odds)` for a game on a given date, and a way to
tell "no archived snapshot" apart from "no value" (05-RESEARCH.md Pitfall 2 — a missing
snapshot must produce a skip, never a silent zero-value decision). Second, the price it
picks must be the price the live bot would have picked; today that selection rule lives
inline in `verdi_deteksjon.py::finn_value_bets` as a triple-nested bookmaker/market/outcome
loop, and copying it into the backtest would recreate for the third time exactly the
duplicated-decision-logic failure mode Phase 2 was built to eliminate (05-RESEARCH.md
"Don't Hand-Roll", Anti-Patterns; CORE-04 parity lineage).

This plan therefore extracts the rule first, rewires the live path onto it (with the
existing, unmodified `tests/test_verdi_deteksjon.py` as the regression net proving the
extraction was behaviour-preserving), and only then builds the archive readers on top of the
now-proven rule. It also splits bet-time and closing access into two separately named public
functions with no public `snapshot_type` parameter — so BT-02 leakage (using a closing price
as a decision input) is prevented structurally, not by a comment.

Purpose: BT-01 needs archived prices in the replay loop, BT-02 needs bet-time and closing
kept apart, and BT-06 needs the closing price fetchable for CLV without ever being reachable
from the decision path.
Output: four new functions in `odds.py`, a smaller and rule-free `finn_value_bets`, and a new
test section in `tests/test_odds.py`.
</objective>
