# Codebase Structure

**Analysis Date:** 2026-08-19

## Directory Layout

There is no `src/`, `tests/`, `lib/`, or package directory. This is a flat collection of numbered top-level scripts plus one shared helper module (`modell_utils.py`). No Python package (`__init__.py`) structure exists.

## Directory Purposes

**Repo root (`.`):**
- Purpose: Holds every script, every generated data artifact, and every piece of persistent state. All scripts assume the current working directory is the repo root (relative filenames like `"nba_modell.pkl"` are used throughout, with no `__file__`-relative path resolution except in `06_bot.py:233` for `PYTHONPATH`).
- Contains: pipeline scripts, shared module, generated CSV/JSON/pickle/HTML artifacts, docs, venv
- Key files: `06_bot.py` (entry point), `modell_utils.py` (shared logic), `requirements.txt` (dependency list)

**`venv/`:**
- Purpose: Local Python 3.10 virtual environment
- Generated: Yes (via `python -m venv venv` or similar, not documented in-repo)
- Committed: No (gitignored)

**Stray/temp artifacts observed but not part of the architecture:**
- `_linux_pkgs/`, `_pip_tmp/`, `_wheels/`, `_test.bin`, `test_write.tmp` — untracked scratch/build artifacts at repo root, not referenced by any script. Not part of the intended structure; likely safe to delete but not owned by this analysis.

## Key File Locations

**Entry Points:**
- `06_bot.py`: Daily orchestrator — the only script with `if __name__ == "__main__":` guard; run via `python 06_bot.py`
- `01_hent_data.py` → `02_feature_engineering.py` → `03_tren_modell.py`: Manual, one-time (or periodic) model (re)training sequence, run in strict order
- `04_value_detector.py`, `05_skadefilter.py`: Runnable standalone for manual/ad hoc checking, or invoked by `06_bot.py` via `subprocess`

**Configuration:**
- No dedicated config file/format (no `.env`, no YAML/TOML config). Configuration is hardcoded as module-level constants at the top of each script:
  - `04_value_detector.py:30-33` — `API_NØKKEL` (Odds API key, hardcoded secret), `MIN_VALUE_TERSKEL`, `MIN_ODDS`, `MAX_ODDS`
  - `05_skadefilter.py:21-22` — `ANTALL_TOPPSPILLERE`, `MIN_MINUTTER`
  - `06_bot.py:33-39` — `STARTKAPITAL`, `KELLY_FRAKSJON`, `MAX_INNSATS`, `MIN_INNSATS`, `BANKROLL_FIL`, `BETS_FIL`, `DASHBOARD_FIL`
- `requirements.txt`: pinned minimum versions for `nba_api`, `pandas`, `numpy`, `scikit-learn`, `xgboost`, `requests`

**Core Logic:**
- `modell_utils.py`: `KalibrertModell` class — shared between training (`03`) and inference (`04`)
- `06_bot.py`: bankroll/Kelly-stake logic (`beregn_innsats`), settlement logic (`sjekk_resultater`), dashboard HTML generation (`generer_dashboard`)

**Testing:**
- None. No test files, test framework, or `tests/` directory exist in the repo.

## Naming Conventions

**Files:**
- Pipeline stage scripts use a two-digit numeric prefix + Norwegian snake_case description: `01_hent_data.py`, `02_feature_engineering.py` (mixed language — `feature_engineering` is English), `03_tren_modell.py`, `04_value_detector.py` (English), `05_skadefilter.py`, `06_bot.py`. The numeric prefix encodes execution order for the training pipeline (01→03) and, loosely, for the daily pipeline (04→05, then 06 orchestrates both).
- Non-pipeline helper/debug scripts have no numeric prefix and use plain snake_case: `modell_utils.py`, `debug_kamp.py`.
- Generated data files use Norwegian snake_case describing content + stage: `nba_kamper_raw.csv`, `nba_features.csv`, `nba_modell.pkl`, `value_bets_idag.csv` ("idag" = "today"), `value_bets_med_skadefilter.csv` ("med" = "with").
- State files use plain English snake_case: `bankroll.json`, `bets.json`.

**Directories:**
- None beyond `venv/` (standard virtualenv naming) — no other project directories exist.

**Code-level naming (relevant when adding to existing files):**
- Variables/functions are Norwegian (`hent_bankroll`, `lagre_json`, `beregn_innsats`, `kjør_pipeline`, `plasser_bets`) — new code in these files should match this convention rather than introducing English names.
- Constants are `SCREAMING_SNAKE_CASE` in Norwegian (`STARTKAPITAL`, `KELLY_FRAKSJON`, `MIN_VALUE_TERSKEL`).
- DataFrame columns mix Norwegian labels for display (`"Kamp"`, `"Bet"`, `"Modell %"`) with English/uppercase stat abbreviations inherited from `nba_api` (`PTS`, `FG_PCT`, `REB`, `AST`, `TOV`, `PLUS_MINUS`) and derived prefixes `HJEMME_RULL_*` / `BORTE_RULL_*` / `DIFF_*` (home/away rolling stat / difference).

## Where to Add New Code

**New pipeline stage (e.g., a new signal/filter before betting):**
- Add a new numbered script following the existing convention (e.g., `05b_back_to_back_filter.py` or renumber to `06_...` and shift `bot.py` to `07_bot.py`), reading the previous stage's CSV and writing its own CSV with the same row-identity columns (`Kamp`, `Bet`, `KampDato`) so `06_bot.py` (or its renumbered successor) can chain it into `kjør_pipeline()`.
- Wire it into `06_bot.py::kjør_pipeline()` as an additional `subprocess.run([sys.executable, "0N_new_stage.py"], ...)` call, following the existing pattern at `06_bot.py:229-253`.

**New shared logic (used by 2+ scripts):**
- Add to `modell_utils.py` rather than duplicating in each script — this is the established (if underused) pattern for cross-script shared code. Good candidate: a single `hent_lag_oppslag()` / `finn_lag_id()` helper to replace the four duplicated team-lookup implementations (see ARCHITECTURE.md Anti-Patterns).

**New feature for the ML model:**
- Must be added in **two places** to stay consistent: the historical/batch computation in `02_feature_engineering.py` (inside `beregn_lag_form()` and the `stats_kolonner` list) and the live/inference computation in `04_value_detector.py` (inside the `stats` list and `feature_rad` construction, `04_value_detector.py:161-166`). After changing `02`, `03_tren_modell.py` must be re-run to retrain on the new feature set before `04_value_detector.py` can use it (the pickled `feature_kolonner` list controls what `04` selects at inference time).

**New configuration/threshold:**
- Add as a module-level constant near the top of the relevant script, following the existing `SCREAMING_SNAKE_CASE` convention (see `04_value_detector.py:30-33`, `06_bot.py:33-39`). There is no central config file to extend.

**Tests (none currently exist):**
- No test directory or framework is set up. If introducing tests, the natural approach given the current single-file-per-stage structure would be a `tests/` directory with one test module per stage, but this would require first refactoring the numbered scripts to expose importable functions (see ARCHITECTURE.md Anti-Patterns: "Top-level module code instead of functions/`main()`") since none of scripts 01–05 currently define functions or guard against import-time side effects.
